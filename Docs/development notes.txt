# THE SIXTH RITU — DEVELOPMENT NOTES

## 1. PROJECT OBJECTIVE

Build The Sixth Ritu as a production-quality, premium luxury fragrance e-commerce website.

This project must NOT be treated as:
- A static landing page
- A generic HTML template
- A basic Shopify-style storefront
- A visual-only prototype
- A desktop-only website

The architecture must support a complete modern e-commerce experience and future backend integrations.

Before development begins, read:

1. `content.md`
2. `design-system.md`
3. `development-notes.md`

Treat these files as the primary project specification.

---

# 2. RECOMMENDED TECHNOLOGY

Preferred stack:

- Next.js
- React
- TypeScript
- Modern CSS architecture
- GSAP where advanced scroll/timeline animation is required
- Motion / Framer Motion for component and UI transitions
- Swiper or an equivalent lightweight library for sliders where appropriate
- Lucide React or another consistent lightweight icon system

Use the current stable and mutually compatible package versions available in the project environment.

Do not blindly install unnecessary dependencies.

---

# 3. NEXT.JS ARCHITECTURE

Use modern Next.js architecture.

Preferred structure:

src/
├── app/
├── components/
├── sections/
├── data/
├── lib/
├── hooks/
├── types/
├── styles/
└── utils/

public/
├── images/
├── products/
├── banners/
├── brand/
└── icons/

Keep the project modular and maintainable.

Do not put the complete homepage inside one massive component.

# 7. PRODUCT IMAGE RULE

Actual supplied product images are priority assets.

Map each supplied image to the correct fragrance.

Never substitute an actual supplied product image with an AI-generated bottle.

Never modify:
- Product branding
- Bottle shape
- Packaging
- Label
- Logo
- Product colour

Do not distort product images.

Use correct `object-fit` and aspect ratios.

---

# 8. PLACEHOLDER ASSET STRATEGY

Some final campaign banners or lifestyle photography may not initially be available.

In such cases:

- Build the complete section
- Use tasteful temporary imagery/placeholders
- Keep assets replaceable
- Do not make layout dependent on one temporary image

All temporary content should be easy to identify and replace.

Do not use ugly grey placeholder boxes in the visible premium UI.

# 12. MOBILE IMPLEMENTATION

Mobile experience is a first-class requirement.

Mobile should feel almost like a premium shopping application.

Requirements:

- Compact header
- Touch-friendly navigation
- Swipeable hero
- Swipeable galleries
- Correct image ratios
- Compact product cards
- Proper typography hierarchy
- Easy quantity controls
- Accessible cart
- Comfortable buttons
- Optimized forms
- Correct spacing
- Sticky purchase CTA where useful

Never allow:

- Horizontal page overflow
- Clipped headings
- Tiny buttons
- Text outside buttons
- Desktop-sized empty spaces
- Oversized typography
- Broken two-column sections
- Unusable hover-dependent interactions

Any hover-only feature must have a touch alternative.

---

# 13. TABLET IMPLEMENTATION

Tablet must not be ignored.

- Header behavior

- Sliders
- Forms
- Footer columns
- Product page gallery

Use tablet-specific layout adjustments where required.

---

# 14. ANIMATION ARCHITECTURE

Animations should reinforce luxury.

Use GSAP only where it provides meaningful benefit, such as:

- ScrollTrigger sequences
- Advanced text reveals
- Controlled parallax
- Timeline-based storytelling
- Six Seasons transition
- Premium hero sequences

Use Motion / Framer Motion for:

- Component entrance/exit
- Menu transitions
- Cart drawer
- Modals
- Hover/tap interactions
- Small UI transitions
- Page-level transitions where appropriate

Do not use multiple animation libraries for the same simple effect.

---

# 15. ANIMATION PERFORMANCE

Prefer animation of:

transform
opacity

Avoid continuously animating expensive properties.

Avoid excessive:
- blur()
- box-shadow animation
- filter animation
- huge background movement

Do not create scroll-jacking.

Native scrolling must remain predictable.

Animations should never block:
- Navigation
- Add to Cart
- Checkout
- Forms
- Product interaction

---

# 16. REDUCED MOTION

Respect:

`prefers-reduced-motion`

Users requesting reduced motion should receive a stable and usable experience without essential information being hidden.
